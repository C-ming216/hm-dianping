# 2026-08-09

## Debug: ClassNotFoundException + Maven dependency errors

用户改了 Spring Boot 父版本后启动报错，从两次报错逐层定位：

1. 第一次：`ClassNotFoundException: com.hmdp.HmDianPingApplication`
   - 原因：`target/classes/` 下没有 `com/` 子目录，源码未被编译
   - 解决：执行 `mvn clean compile`

2. 第二次：`mvn clean compile` 后报 dependency.version missing（mysql-connector-java + mybatis-plus-boot-starter）
   - 原因：原 `pom.xml` 写的是 `spring-boot-starter-parent:4.1.0`，该版本不可用，BOM 加载失败，导致版本继承断裂
   - 修复（已写入 pom.xml）：
     - parent 改回 `2.7.18`（黑马点评课程标准 + 兼容 Java 8）
     - `mybatis-plus-boot-starter` 显式加 `<version>3.5.5</version>`

后续建议：用户在 IDEA 中点 Maven → Reimport 让依赖重新解析，然后 `mvn clean compile` 验证。

## Debug 第二轮：ClassNotFoundException 反复出现

用户按指引 Reload 后再次 ClassNotFoundException，深入排查发现：

1. **`mvn` 命令本身就坏**：`找不到或无法加载主类 org.codehaus.plexus.classworlds.launcher.Launcher`。PATH 没生效。解决：用绝对路径 `E:/SDK/apache-maven-3.9.16/bin/mvn.cmd` 直跑。

2. **本地仓库里只缓存了 `spring-boot-starter-parent:4.0.7`**：意味着用户其实之前在用 Spring Boot 4，但源码是 `javax.annotation.*` 的 2.x 写法 —— 不兼容。

3. **JDK 实际是 21.0.6**，但 pom 里写 `java.version=1.8`。结合源码用 `javax.*`，强行升 jakarta 或升级 JDK 都不合理。

**最终修复方案**（pom.xml 已固化）：
- parent `4.0.7` → `2.7.18`
- `java.version` 保持 `1.8`
- mysql 坐标保持 `mysql:mysql-connector-java`，显式写 `<version>8.0.33</version>`
- mybatis-plus-boot-starter 显式 `<version>3.5.5</version>`

**编译验证**：`mvn clean compile` 联网模式跑通，63 源文件全部编译成功，`target/classes/com/hmdp/HmDianPingApplication.class` 已生成。

整段调试串起来看，是个**链式踩坑**：
1. 用户原本在用 Spring Boot 4.0.7 + JDK 21 + javax 源码 = 本来就跑不起来
2. 用户改 pom 想"修复"，手滑改成 4.1.0，更糟
3. 我第一轮改成 2.7.18 但 mysql 没显式版本（依赖 BOM 在某些环境不接管）
4. 第二轮用绝对路径 + 联网 + 显式版本，最终跑通

**教训**：用户环境情况比想象的复杂（缓存错乱、mvn 命令坏、源码用旧 API），下次进这类 Java Spring Boot 教程项目，先查本地仓库有什么版本、查系统 JDK 是哪个版本，再决定往哪升。
